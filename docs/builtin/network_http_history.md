# Nodejs 支持 HTTP 的演进历史

在 Node.js 中，`http`、`https`、`http2` 和 `http3` 的演进，本质上就是 Node.js 对 Web 网络协议从**基础支持**到**性能优化**，再到**底层革命**的完整映射。

## 🌐 1. 基石阶段：HTTP/1.1 与 HTTPS（2009年 - 2015年）

- HTTP (http 模块)：Node.js 在 2009 年诞生时，内置的 `http` 模块就是基于 **HTTP/1.1** 协议的。它解决了传统服务器的高并发瓶颈，但依然受限于 HTTP/1.1 的“队头阻塞”（一个连接只能按顺序处理请求）和明文传输的缺陷。
- HTTPS (https 模块)：为了解决 HTTP 明文传输的安全隐患，Node.js 提供了 `https` 模块。它本质上是在 HTTP 和 TCP 之间加了一层 SSL/TLS 加密层。在很长一段时间里，开发者通过 `https` 模块来保障数据传输的安全，但它底层的传输机制依然是 HTTP/1.1。

## ⚡ 2. 性能跃迁阶段：HTTP/2（2015年 - 2022年）

2015年 HTTP/2 标准正式发布。为了支持这一高性能协议，Node.js 在 **v8.4.0** 版本中正式引入了原生的 `http2` 模块。

- 核心突破：它通过**多路复用**（一个连接并行传输多个请求）和**头部压缩**，彻底解决了应用层的队头阻塞问题。
- 强制安全：虽然标准未强制，但主流浏览器和 Node.js 的最佳实践都要求 HTTP/2 必须运行在 HTTPS（TLS）之上。因此，`http2` 模块通常与 TLS 证书配置绑定使用。

## 🚀 3. 底层革命与大一统阶段：HTTP/3（2022年 - 2026年）

2022年 HTTP/3 正式标准化，它将底层传输协议从 TCP 换成了 **UDP (QUIC)** 协议支持（通过更新 `ngtcp2` 和 `nghttp3` 等底层依赖），彻底解决了 TCP 层面的队头阻塞，并实现了 0-RTT 极速连接。

Node.js 在随后版本更新中，经历了从第三方库依赖到内置实验性 `quic` 模块的探索期，到最后默认开启的三个阶段。

1. 早期探索与实验阶段（约 Node.js v14 - v24）：在较早的版本中，Node.js 对 HTTP/3 的支持确实处于起步阶段。开发者需要通过实验性的 `quic` 模块，或者依赖第三方库（如 `http3`）才能使用 HTTP/3。在这个阶段，HTTP/3 长期处于实验性状态，API 也不够稳定，不建议在生产环境中直接使用。
2. 逐步成熟与稳定阶段（Node.js v25）：到了 Node.js v25 版本（2025年底发布），HTTP/3 的支持迎来了重大突破。该版本内置了更完善的 QUIC 协议支持（通过更新 `ngtcp2` 和 `nghttp3` 等底层依赖），并将 HTTP/3 设为**默认开启**。这意味着开发者不再需要复杂的额外配置，就可以开始体验和使用 HTTP/3 带来的性能红利。
3. 全面默认与生产就绪阶段（Node.js 2026 / v26+）：进入 2026 年，新一代的 Node.js 已经将 HTTP/3 彻底作为**默认的网络传输协议**。现在的 Node.js 在启动服务时会自动基于 QUIC 协议（底层使用 UDP）使用 HTTP/3，并且能够自动向下兼容 HTTP/2 和 HTTP/1.1。

在最新版本中，使用 HTTP/3 变得极其简单，几乎实现了“零配置”：

```javascript
// 2026年新一代 Node.js：使用原生 http 模块，默认自动启用 HTTP/3
const http = require("http")

const server = http.createServer((req, res) => {
  res.writeHead(200, { "Content-Type": "text/plain" })
  res.end("Node.js 默认 HTTP/3，传输更快更稳定！")
})

server.listen(3000, () => {
  console.log("HTTP/3 服务器已启动")
})
```

所以，现在的 Node.js 已经完全拥抱了下一代网络协议，你可以放心地在项目中使用 HTTP/3 来提升应用的网络性能。

- 大一统：你不再需要刻意引入 `http3` 模块。使用最原始的 `require('http')` 或 `require('https')` 创建服务器时，Node.js 会自动基于 QUIC 协议启用 HTTP/3，并向下兼容 HTTP/2 和 HTTP/1.1。
- 零配置：底层自动处理协议协商，开发者只需关注业务逻辑。

如果你正在维护老项目，可能会看到 `http`、`https` 和 `http2` 模块混用的情况。但在新项目中，直接使用基础的 `http` 或 `https` 模块即可，Node.js 的底层引擎已经帮你自动跑在了最快的 HTTP/3 轨道上。唯一需要注意的是，由于 HTTP/3 基于 UDP，如果你的服务器开启了防火墙，**记得开放对应的 UDP 端口**（通常是 UDP 443），否则客户端将无法建立 HTTP/3 连接。
